## Navigation and links

Maintain the shared header and footer centrally in `site.yaml`. A header link is active when its target exactly matches the current page URL; for example, “Showcase” is marked on `/showcase/`. Child pages do not automatically activate the parent navigation item.

The examples below show links within page content. Each opens with a preview; the Code tab provides the matching Markdown or MDX for an existing content file. The MDX example includes its required import.

**Atomic Design:** Organisms `Header` and `Footer` provide the shared page frame. The content link examples use Markdown.

Component paths within `src/themes/default/components/`: `organisms/Header/` and `organisms/Footer/`.

### Links with query parameters

Links can include query parameters. The page target stays the same, and adding the base path preserves the query string.

<Tabs label="Links with query parameters: Preview and code" variant="border">
    <Tab title="Preview">

        [Open the FAQ from the showcase](/faq/?ref=showcase)

        [Open Info with a referral parameter](/info/?ref=navigation)

    </Tab>
    <Tab title="Code">
        ````markdown
        [Open the FAQ from the showcase](/faq/?ref=showcase)

        [Open Info with a referral parameter](/info/?ref=navigation)
        ````
    </Tab>

</Tabs>

### External links and email

External web links retain their full URL and open in a new browser tab. An email link opens the mail application. Sproutsite's contact address is grow@sproutsite.dev.

### Further actions

CardActions displays navigation links inside a card as buttons. They remain semantic links because they lead to other pages.

<Tabs label="Further actions: Preview and code" variant="border">

            #### Explore the layout

            Explore column layouts in the showcase or read the component documentation.

            <CardActions>
                [View layouts](/showcase/layout/)
                [Understand the components](/documentation/layout/)

        </Card>

    </Tab>
