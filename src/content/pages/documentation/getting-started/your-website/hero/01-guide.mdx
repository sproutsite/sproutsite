## Change the introduction and background

<Alert variant="info" style="soft">
    Partly available. The steps below distinguish existing features from
    extensions that remain open.
</Alert>

Edit `src/content/pages/hero.md` for the homepage, or the `hero.md` in another page directory. The German counterpart is `hero.de.md`. The hero owns the visible H1; `page.yaml` still supplies the browser title and description.

```yaml
---
title: Welcome to my workshop
eyebrow: Handmade in Bristol
type: big
classes: null
background-image: ./_assets/workshop.jpg
---
Furniture, repairs and the stories behind them.
```

Create the `_assets` directory beside this hero and add your own `workshop.jpg`. This local setting overrides `hero.background-image` in `site.yaml`. Astro optimizes relative raster images; SVGs and public files remain unchanged. You can alternatively use a public path such as `/backgrounds/hero-waves.svg`. The background is decorative, so keep meaningful information in text or regular content images.

`classes: null` removes the global hero classes; the background image is selected independently. Without a local image setting, the global default applies. Set `background-image: null` to remove it on one page. With neither a global nor local image, no image is rendered; CSS gradients remain. Test narrow screens as well as desktop.

### One background for all pages

Place the file at a path such as `public/backgrounds/hero-waves.svg`. Add this to the relevant site configuration:

```yaml
hero:
    classes:
        - ss-hero--theme-1
    background-image: /backgrounds/hero-waves.svg
```

The image also applies to title areas without `hero.md`, the blog overview and error pages. Omit `public`, language prefixes and deployment subpaths from the URL. The theme applies `base` once. The file belongs to your website, rather than being loaded from a fixed package location.

### Size and actions

Use `type: small` for a compact introduction; omission also means `small`. `big` adds the homepage spacing, with a smaller increase on mobile. Optional `claim`, `actions` and `tagline` fields let you add a supporting line, one or two links and a final short statement. For example:

```yaml
actions:
    - label: See my work
      href: /gallery/
      variant: primary
    - label: Get in touch
      href: /contact/
      variant: secondary
```

Create these target pages before adding their links. Use the [content reference](/documentation/content/) for the complete hero fields.

### Still open

`fullscreen` is a prepared type and CSS class, not a completed full-viewport layout. That layout remains open. Global background images and replacing SVG waves are already supported through `hero.background-image`.
