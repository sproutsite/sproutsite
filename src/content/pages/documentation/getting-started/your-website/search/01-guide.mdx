## Help visitors find a page

<Alert variant="info" style="soft">
    These steps assume that your website starter includes the Pagefind build
    integration and the search button in the header. Try the working example in
    this site’s navigation. It searches the documentation and Showcase.
</Alert>

### Turn on search

Open `src/content/site.yaml` in your website project and add or update this top-level setting:

```yaml
search:
    enabled: true
```

In a bilingual project, set it in the shared `site.yaml`. The prepared header adds a magnifying glass on desktop and mobile. Click it to open the search dialog. Set `enabled: false` to turn search off.

### Build the search index and test it locally

From your website project folder, run:

```sh
npm run build
npm run dev
```

Astro generates the HTML first. The prepared integration then passes the main content of the selected pages to Pagefind, which writes the index and browser files to `dist/pagefind/`. The search dialog loads that bundle from your own site when someone searches. The integration connects the dialog to the bundle and accounts for the site’s base path, including deployments under a subpath such as `/demo/`.

Open the URL printed by the dev server and search for a phrase from one of your pages. The dev server reads the most recent built index, so rebuild and reload the page after editing searchable content. To check the exact files you will deploy, run `npm run preview` after the build.

### Read and open results

The dialog searches in the active language. It shows an excerpt with matching words highlighted, a rank badge, the Pagefind relevance score, and the exact destination URL. The highest score appears first. The score compares results for the current query. It is not a percentage. When a match has a suitable section link, the result opens that section.

From the search field, press `↓` to focus the first result. Use `↑` and `↓` to move through results, `Enter` to open one, and `Esc` to close the dialog. You can also use `Tab` to navigate the controls.

### Publish the search with your website

Publish the full `dist/` directory, including `dist/pagefind/`, from the same build. Keep the generated index out of Git. Searches run in the visitor’s browser using files served by your website.

If the search reports that it is unavailable, first check that `pagefind/pagefind.js` is served under the same base path as your pages. If the server sets a Content Security Policy, allow `'wasm-unsafe-eval'` in `script-src` for Pagefind’s WebAssembly. [Pagefind hosting documentation](https://pagefind.app/docs/hosting/)
