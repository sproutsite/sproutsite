## Set up translated pages deliberately

### Create a bilingual website

Choose one command. The value of `--language` sets the default language at `/`.

```sh
# German at /, English at /en/
npm create sproutsite@latest my-website -- --language de --bilingual

# English at /, German at /de/
npm create sproutsite@latest my-website -- --language en --bilingual
```

Accept the dependency installation when prompted, then start the website.

```sh
cd my-website
npm run dev
```

Open the address printed in the terminal. Try the language switcher on the homepage and on the About page. With German as the default, it links `/ueber-uns/` and `/en/about/`. With English as the default, it links `/about/` and `/de/ueber-uns/`.

Edit both versions in the same directory under `src/content/pages/`. For the About page, edit `about/01-introduction.md` in English and `about/01-introduction.de.md` in German. The corresponding `page.yaml` and `page.de.yaml` hold their titles and descriptions. Edit navigation and footer copy for the default language in `src/content/site.yaml`. For the other language, use `site.en.yaml` in the German-first starter or `site.de.yaml` in the English-first starter.

A single-language English starter serves English at `/`; the German starter serves German at `/`. A translated website adds files for the same page identity, rather than creating unrelated copies of each page.

### Add German to an existing English website

The demo uses English at `/` and German below `/de/`. In `site.yaml`, set `i18n: { locale: en, defaultLocale: en, locales: [en, de] }`. `site.de.yaml` needs only `i18n.locale: de` and German overrides such as navigation and footer copy. Objects inherit individual fields; arrays replace entire base lists. Add `src/pages/de/[...slug].astro` using `sproutsite/page` and `getSproutsiteStaticPaths('de')`.

Add German files beside their English counterparts: `page.de.yaml`, `hero.de.md` and sections such as `01-introduction.de.md`. Match section numbers and base filenames. A German `url` value may translate the page's own URL segment, for example `about` to `ueber-uns`; it does not change the shared source directory.

### Language selection

Add this entry to the existing `header.links` array:

```yaml
- type: language-switcher
```

The switcher lists configured languages, links to the matching translated page and falls back to that language's homepage when a counterpart is absent. Optional `footer.languageSwitcher: true` uses the same behavior in the footer. Sproutsite does not translate text automatically.

### Starting from a German-only website

Set `i18n: { locale: de, defaultLocale: de, locales: [de, en] }` in the base. Put English labels in `site.en.yaml` with `i18n.locale: en`. Source conventions stay unchanged: unsuffixed files are English; `.de` files are German.

The standard Astro route files must match: `src/pages/[...slug].astro` calls `getSproutsiteStaticPaths()` for the default locale; `src/pages/en/[...slug].astro` calls `getSproutsiteStaticPaths('en')`. Both use `sproutsite/page`. If you move existing German routes from `/de/` to `/`, remove their old route file and configure redirects for published URLs. Check language selection, canonicals, and the sitemap before deployment.

Further languages still require translated theme messages and extended content-locale handling. A locale identifier in configuration does not translate content.
