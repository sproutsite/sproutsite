## Give every page useful metadata

Each page's `page.yaml` supplies the browser title and meta description. Write a specific title and a short description of what visitors can find there. The hero title is the visible H1 and may be worded differently.

```yaml
title: Furniture repairs in Bristol – Willow Workshop
description: Repairs and restoration for everyday wooden furniture. See recent work and ask about your piece.
```

For a German translation, edit `page.de.yaml`. Keep page titles distinct. Use meaningful H2 and H3 headings, descriptive links and accurate image alternative text throughout the content.

### URLs and sitemap

Set the real production `url` and `base` in your site configuration before building. Sproutsite derives canonical addresses and produces `sitemap.xml` with page locations, modification dates and language alternatives where translations exist. The output must be deployed with the rest of `dist`.

An optional page `url` changes its own single URL segment. Changing a published address can break existing links, so arrange redirects at your host. A sitemap helps describe your pages; it does not guarantee indexing or ranking.

### Reference the sitemap in robots.txt

Help crawlers find the sitemap by listing its full production URL in robots.txt at the domain root. The Sproutsite demo generates this file through a native Astro endpoint. You can add the same entry to your website project as src/pages/robots.txt.ts:

```ts
import type { APIRoute } from 'astro';

export const prerender = true;

export const GET: APIRoute = ({ site }) => {
    if (!site) throw new Error('robots.txt requires the production site URL.');
    const sitemap = new URL(
        `${import.meta.env.BASE_URL.replace(/\/$/, '')}/sitemap.xml`,
        site,
    );
    return new Response(
        `User-agent: *\nAllow: /\n\nSitemap: ${sitemap.href}\n`,
        { headers: { 'Content-Type': 'text/plain; charset=utf-8' } },
    );
};
```

The URL comes from the Astro configuration that Sproutsite derives from your website settings. The build writes robots.txt as a static file to dist. If your website uses a subpath such as /studio/, also list the sitemap in the domain-root robots.txt. A file served only at /studio/robots.txt is not sufficient.

If you already have a robots.txt or matching endpoint, add the Sitemap entry there and preserve its existing rules. The example allows crawling; it does not protect private content or staging websites.

### Offer a guide for coding agents

An optional `llms.txt` can describe your website and link to its most useful pages. The Sproutsite website publishes a compact English guide and points to it from each page's HTML head using `rel="describedby"`. It also identifies the German documentation. This is a voluntary format, not an indexing requirement or a promise that an agent will use it.

Your website does not inherit Sproutsite's guide. For a simple static version, create `public/llms.txt` with a Markdown H1, a short blockquote summary and grouped links with descriptions. Describe your own website and use its full production URLs, including any deployment subpath. An English guide is sufficient when both language versions provide equivalent information; include localized resources when their content differs.

To announce it in Sproutsite's shared HTML document, declare an optional `llmsUrl?: string` property in `App.Locals` in `src/env.d.ts`, then set `locals.llmsUrl` to the absolute guide URL in native Astro middleware at `src/middleware.ts`. Preserve any existing middleware. Without that value, no discovery link is rendered. For a build-generated guide, a prerendered `src/pages/llms.txt.ts` endpoint can replace the public file; use one source only. The Sproutsite repository contains this endpoint and middleware as a working example. Deploy the generated file with the complete build and update it when your content changes.

### Describe your pages with structured data

Sproutsite automatically adds JSON-LD to the HTML head at build time. Regular pages describe their title, description, canonical URL and language as `WebPage`. The homepage in the default language also describes the website as `WebSite`; translations reference that same website. Your existing page metadata and website settings supply these values, so there is no separate list to maintain.

Blog articles additionally provide `BlogPosting` with their visible hero headline, publication date and optimized article image. If you want to identify the author publicly, add this optional object to the article's `page.yaml` and its translated metadata:

```yaml
author:
    name: Example Author
    url: https://example.org/about/
```

Use the actual person's name and profile page. The URL is optional and must use HTTP or HTTPS. The default theme displays the same author beside the article date. Without this object, Sproutsite omits the author instead of copying the website operator from legal settings. It does not invent modification dates, publishers or ratings, and error pages have no structured data.

After deployment, check the generated JSON-LD with the Schema.org validator or Google's Rich Results Test. These tools serve different purposes: valid Schema.org data does not necessarily qualify for a Google rich result, and no search presentation is guaranteed.

### Check what is actually public

Inspect the built page source for the title, description, canonical URL and language links. Confirm that staging protection is removed only when the website should become public. `robots.txt` is not access control.

### Choose a sharing image

Set `branding.sharingImage.src` and `branding.sharingImage.alt` in `src/content/site.yaml`. Use a local PNG, JPEG or WebP from `public/`, for example `/branding/sharing-image.png`. Sproutsite reads its dimensions and generates absolute Open Graph and Twitter image URLs from the production URL and deployment base. A language configuration can override the image or its alternative text.

This is a website-wide default. A blog card image does not automatically replace it; per-page image overrides are not part of this setting. See [your branding](/documentation/getting-started/your-website/branding/) for the complete configuration.
