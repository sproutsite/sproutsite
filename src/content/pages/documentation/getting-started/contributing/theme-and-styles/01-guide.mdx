## Change the default theme in its source checkout

This guide is for Sproutsite contributors editing `src/themes/default/`. It is not a consumer override API. The separate [future extension topic](/documentation/getting-started/contributing/theme-extensions/) records that missing public workflow.

### Preserve the style entry point

`src/themes/default/styles/theme.css` is the only default-theme style entry. It loads the framework, global foundations, semantic tone mappings and component styles in a documented order. Keep that cascade stable unless the result is checked deliberately.

Global foundations live in `styles/foundation/`; semantic section tones live in `styles/themes/section-tones.css`. Concrete component presentation belongs in that component’s own CSS, not in a growing global overrides file.

### Reuse the existing design

Use the current navy, blue, teal and restrained green palette. Preserve the shared `site-shell` edge, typography hierarchy and responsive behavior. Read the active tokens and theme mappings before adding another color or spacing value.

Theme classes use `ss-` and native CSS nesting. Scope elements and modifiers inside their component block. Content files do not take arbitrary styling classes or inline styles.

### Verify all relevant states

Check default, muted and brand contexts when they apply. A small spacing change should not hide focus, cut off a tooltip or create horizontal overflow. Test desktop and mobile, then use [Storybook](/documentation/getting-started/contributing/storybook/) and the [accessibility checks](/documentation/getting-started/contributing/accessibility/) for the affected component.
