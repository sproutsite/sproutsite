## Make theme changes possible in a website project

<Alert variant="warning" style="soft">
    Open – future extension. This page describes the goal; a supported
    implementation is not yet available.
</Alert>

The goal is a supported way for a website’s own team to keep the default theme and adjust selected styles or components, or to choose an independent presentation without migrating content.

### What exists already

Core and default-theme source are separated. Contributors can edit that source in this checkout, and existing typography, hero and component settings cover specific needs. This does not yet amount to a public consumer theme API.

### Decisions still needed

Define a small public entry for local styles or component replacement, its loading order and compatibility guarantees. Decide how supported tokens and content components are exposed. Do not invent a theme loader or configuration flag in documentation before it exists.

### Acceptance criteria

- Existing website content still validates and renders.
- Default-theme users need no migration for an optional extension.
- Base paths, language links, metadata and error pages still work.
- The extension has focused source tests, an installed-consumer example and accessible responsive output.

The [theme source guide](/documentation/getting-started/contributing/theme-and-styles/) covers work that is possible today. This page records an implementation goal; it is not a working override recipe or a release commitment.
