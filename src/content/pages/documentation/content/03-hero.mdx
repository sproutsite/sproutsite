## Introduce a page with hero.md

A `hero.md` file activates the shared hero and provides its visible H1, eyebrow, tone, and Markdown introduction. The optional `claim` adds a prominent line below the H1; `actions` adds one or two buttons, and `tagline` appears below them.

```yaml
---
title: Page title in the hero
type: small
titleHighlight: hero
eyebrow: Context
tone: brand
background-image: ./_assets/hero-visual.png
claim: A memorable statement.
actions:
    - label: Get started
      href: /documentation/getting-started/
      variant: primary
tagline: A short supporting tagline.
---
```

`background-image` references a local image relative to `hero.md`. Astro validates and optimizes the file. The default theme treats it as decoration and adds an overlay to preserve text contrast. Images that convey information belong in a regular section with alternative text instead.

### Prepare the hero type

Set `type` to `small`, `big`, or `fullscreen`. Without this field, the type is `small`. The hero receives the corresponding `ss-hero--small`, `ss-hero--big`, or `ss-hero--fullscreen` class independently of its theme classes. Both homepage translations use `big`; other heroes, the blog overview, and H1 fallbacks use `small`.

The `big` variant adds more space above the hero content. Other variant-specific styling is still being prepared: `small` retains the base presentation, and `fullscreen` does not yet fill the viewport.

### Override or remove classes for one page

A `classes` list replaces `hero-classes` from `site.yaml`. Set `classes: null` to deliberately remove the global classes on one page.

### Hero actions

Each action requires a non-empty `label`, an internal or external `href`, and `variant: primary` or `secondary`. The hero renders the shared Button component. Internal targets remain root-relative and receive the deployment `base` like other content links.

```yaml
classes: null
```
