## Global website settings

`src/content/site.yaml` defines the name, production URL, base path, language, navigation, and footer. Layouts, links, canonical URLs, and the sitemap use these same values.

```yaml
name: Sproutsite
url: https://sproutsite.dev
base: /
i18n:
    locale: en
    defaultLocale: en
    locales:
        - en
```

### Languages and inheritance

`site.yaml` contains shared settings. Keep only German overrides in `site.de.yaml`:

```yaml
i18n:
    locale: de
header:
    links:
        - label: Startseite
          href: /
```

Enable `i18n.locales: [en, de]` in the base first. `i18n.defaultLocale` selects the language without a URL prefix, independently of list order. In the base, `locale` must match `defaultLocale`. Objects inherit individual fields; arrays replace the whole list. A German typography override therefore changes only that field, while a German link list replaces all inherited links. Without a locale file, base settings apply with the requested locale. Production URL, base path, default locale and enabled languages remain shared.

Legacy `language`, `locales`, `links.externalNewTab`, `links.externalIcon` and flat blog fields remain readable. Use grouped settings for new configuration; do not combine old and new spellings for the same group within one file.

Restart `npm run dev` after changing enabled languages, the default locale, production URL, base path or automatic link processing. These settings are also read when Astro loads its configuration.

### Website search

The starter includes optional Pagefind search as of `create-sproutsite@0.4.0`. Set `search.enabled: true` in the shared `site.yaml` and run `npm run build`. The [search guide](/documentation/getting-started/your-website/search/) covers previewing, indexing, and publishing.

### Heading and eyebrow fonts

Choose heading and eyebrow fonts independently in `site.yaml`; override individual fields in `site.de.yaml` when needed:

```yaml
typography:
    headings:
        family: serif
        weight: 500
    eyebrow:
        family: serif
        weight: 500
```

For each area, `family: serif` selects EB Garamond and `family: sans-serif` selects Nunito. `weight` accepts integers from 400 to 800 for EB Garamond and 200 to 1000 for Nunito. Omitted fields default to `family: serif` and `weight: 500`. Locale files inherit these settings unless they override them. The default theme loads the fonts locally. Headings, titles and the header/footer wordmark follow `headings`; eyebrow text follows `eyebrow`. Body text, navigation, buttons and inline emphasis keep their existing typography.

### Website colors

The optional `colors` block configures the shared palette. `surfaces` contains content backgrounds, borders and text. The `primary`, `secondary`, `accent`, `neutral`, `info`, `success`, `warning` and `error` roles each accept `color` and `content`. `brand` controls the CSS colors of the wave-style hero, footer and brand navigation. Omitted fields keep theme defaults; locale files inherit individual values.

```yaml
colors:
    primary:
        color: '#527b37'
        content: '#ffffff'
```

The [website colors guide](/documentation/getting-started/your-website/colors/) explains every field and contrast checks. SVG waves and images retain their embedded colors and need separate editing when required.

### Your own CSS files

Keep small design changes in your website project, for example in `src/styles/custom.css`. Register them through `createSproutsiteConfig({ styles: ['./src/styles/custom.css'] })` in `astro.config.ts`. They are processed after the complete default theme in list order. This technical integration belongs outside `site.yaml`. The [small design changes guide](/documentation/getting-started/your-website/theme-overrides/) explains cascade layers, previewing and package updates.

### Your own header and footer

Set `components: { Header: './src/components/Header.astro', Footer: './src/components/Footer.astro' }` in `createSproutsiteConfig()` inside `astro.config.ts` to select local replacement components. Unspecified areas keep their defaults. Both receive `site` and `route`; `HeaderProps` and `FooterProps` are exported from `sproutsite`. The [header and footer guide](/documentation/getting-started/your-website/header-and-footer/) covers examples and reusing `DefaultHeader` and `DefaultFooter`. This integration belongs outside `site.yaml`.

### Global hero classes

Use `hero.classes` to set theme classes for all heroes and compact H1 fallbacks on pages without `hero.md`. Class names start with `ss-`; they remain theme details rather than a content-layout API.

```yaml
hero:
    classes:
        - ss-hero--theme-1
    background-image: /backgrounds/hero-waves.svg
```

Older configurations used `hero-classes`. Move that list to `hero.classes`; the old key is rejected with a migration hint. The local `classes` field in `hero.md` stays unchanged.

### Global hero background image

Place your image under `public/` and set `hero.background-image` to its website-root-relative path, such as `/backgrounds/hero-waves.svg`. SVG, PNG, JPEG, WebP and AVIF are supported; omit deployment and language prefixes. Public images are delivered unchanged.

A local `background-image` in `hero.md` or `hero.de.md` replaces the global default. Relative local images such as `./_assets/hero.jpg` also work there. Set `background-image: null` to disable the global image on one page. With neither setting, no image is rendered; CSS gradients and other class styles remain. Pages without `hero.md`, the blog overview and error pages also use the global default.

### Position hero and footer images

Add `background-position` under `hero` or `footer` to keep the relevant part of an image in view as it fills the space. Available values are `center`, `top`, `bottom`, `left`, and `right`.

```yaml
hero:
    background-image: /images/workshop.webp
    background-position: center
    background-position-mobile: left
footer:
    background-image: /images/workshop-footer.webp
    background-position: bottom
```

In the default theme, `background-position-mobile` applies below `64rem`. If omitted, the general position applies there too. If neither position is set, the theme or starter keeps its existing crop. Locale files can override either field, and a page can override either hero position in `hero.md` or `hero.de.md`.

If your starter's `src/styles/backgrounds.css` sets `object-position: center bottom` for these images, change those declarations to `--ss-background-default-position: center bottom`. The original crop then serves as the fallback for the YAML settings.

### Footer areas

Control external links independently of the footer layout:

```yaml
links:
    external:
        newTab: true
        icon: true
```

`links.external.newTab` defaults to `true` and automatically adds `target="_blank"` and `rel="noopener noreferrer"` to external web links. Set it to `false` for native same-tab behavior. `links.external.icon` defaults to `false`; enable it for a trailing CSS arrow on external web, email and telephone links. Both options are enabled for this demo. Theme markup remains native `<a>` elements; no Link component is required.

Configure each language's footer in `site.yaml` or `site.de.yaml`. `text` describes your website; `groups` creates titled navigation columns. Optional `icon` values are canonical PascalCase Lucide names. On mobile the columns stack, with icons and arrows beside the links.

```yaml
footer:
    background-image: /backgrounds/footer-waves.svg
    text: Your website description.
    copyright: © 2026 Your organisation
    showVersion: true
    languageSwitcher: true
    groups:
        - title: Explore
          links:
              - label: Contact
                href: /contact/
                icon: Mail
    social:
        title: Follow
        links:
            - platform: github
              label: Sproutsite on GitHub
              href: https://github.com/sproutsite/sproutsite
    links:
        - label: Legal notice
          href: /legal-notice/
```

`links` remains the lower link row and supports existing configurations unchanged. Omit `groups` or `social` to hide those areas. Social platforms currently supported are `github`, `instagram` and `facebook`, using local Simple Icons logos. `label` is the accessible name of each icon link. `showVersion` defaults to `true` and reads the installed library's `VERSION`; set it to `false` to hide it. `copyright` is literal text you maintain yourself. `languageSwitcher` defaults to `false`; enabling it reuses the header's language selection, including matching translated pages and homepage fallback. The dropdown opens upward in the footer. Internal links use the active language and deployment base; external links open in a new tab.

Set `footer.background-image` to a file under `public/`, written as a website-root-relative path without a deployment or language prefix. SVG, PNG, JPEG, WebP and AVIF are supported. A language configuration can override the path or set it to `null` to hide the image. With no image configured, the footer shows its theme gradient.

### Private operator details in the legal notice

The demo's legal-notice pages read the operator's name, address and contact details from the local `.env`. Copy `.env.dist` to `.env` and replace the examples. `.env` is ignored by Git; `.env.dist` contains examples only. The generated HTML intentionally displays the operator details publicly.

Required keys are `LEGAL_NAME`, `LEGAL_STREET`, `LEGAL_POSTAL_CODE`, `LEGAL_CITY`, `LEGAL_COUNTRY` (two-letter country code), `LEGAL_EMAIL` and `LEGAL_LINKEDIN`. Without complete details, `npm run dev` shows marked examples. Builds reject a missing `.env`, invalid or incomplete values, and the unchanged example identity. Restart the dev server after changing `.env`.

The documented MDX component reuses the existing Columns and Feature building blocks:

```mdx
import { LegalIdentity } from 'sproutsite/components';

## Operator

<LegalIdentity />

Responsible: **<LegalIdentity part="name" />**.
```

Omitting `part` selects `contact`, which renders the address and contact details. `part="name"` outputs only the name. There is no Markdown variable substitution. Websites without this component do not require operator variables. Only `.env` is read, not `.env.local` or inherited shell variables. Unrelated variables are not rendered.

### Hosting and privacy information

For privacy policies, `LegalIdentity part="controller"` renders operator cards without LinkedIn, and `part="email"` inserts an email link from `.env`. `PrivacyInfrastructure` reads hosting and retention metadata server-side from the same file:

```mdx
import { PrivacyInfrastructure } from 'sproutsite/components';

## Hosting

<PrivacyInfrastructure />

Size limit: <PrivacyInfrastructure part="log-size-limit" />.

<PrivacyInfrastructure part="log-retention" />

Email upper limit: <PrivacyInfrastructure part="email-retention" /> months.
```

The `PRIVACY_HOST_*` and `PRIVACY_SERVER_*` fields, rotation size and email period are listed in `.env.dist`. Pages using this component require complete valid hosting metadata when built. Development previews otherwise show examples.

Leave `PRIVACY_LOG_RETENTION_DAYS` empty until a time-based policy is implemented. A number applies to the configured nginx access/error logs and shared Traefik operational/error logs during normal operation. The demo describes hourly rotation, five-minute age cleanup and cleanup on the next start after a service interruption. External copies and backups are not covered by that rule. `PRIVACY_LOG_SIZE_LIMIT_MIB` records the additional limit in MiB; it is not a time limit.

`PRIVACY_EMAIL_RETENTION_MONTHS` records the chosen maximum for completed ordinary inquiries in the active mailbox. Copies and backups require separate verification. These variables change the published text; they do not configure the server or mailbox or delete data.
